# OTBM Atlas — GitHub-hosted render to private Synology deployment

This package is the transport boundary for canonical OTBM Atlas deployment.

GitHub-hosted Linux runners remain the render compute. The owner's Synology is used only as a temporary authenticated receiver, verifier/assembler, deployment coordinator and private static origin. Synology does not parse/render the full OTBM world as deployment compute.

## Canonical flow

```text
explicit full-world deployment request on main
        |
        +--> Synology: isolated generation + write-only receiver + temporary outbound tunnel
        |
        +--> ubuntu-latest: canonical 32-shard planner
        |
        +--> 32 x ubuntu-latest
        |      render one weighted assignment
        |      verify_world_shard
        |      stream verified bundle directly to Synology
        |
        +--> ubuntu-latest
        |      build global factual/search/viewer/tile-inspector bundle only
        |      no world detail/environment rendering
        |      stream directly to Synology
        |
        +--> exact 3494-chunk certification
        |
        +--> Synology
               verify all received shard corpora independently
               assemble complete publication
               FULL_RUNTIME_READY publication gate
               refuse current-state drift
               current -> previous
               assembled -> current
               recreate only otheryn-atlas-preview
               health + manifest verification
               activate receipt or rollback
               remove receiver/tunnel/token
```

PR/labeled full-world certification never enters deployment mode. Only an explicit deployment request merged to `main` (or a manual `workflow_dispatch` bound to the exact main SHA) can authorize Synology mutation.

## Transport boundary

The receiver is `receiver.py` and exposes only:

- authenticated `GET /health`;
- authenticated `PUT /v1/bundles/<bundle>/parts/part-NNNN`;
- authenticated `POST /v1/bundles/<bundle>/complete`.

There is no shell, arbitrary path, directory listing or file-read endpoint. Every payload part has a declared SHA-256. Completion requires an exact contiguous part manifest, reconstructs an archive whose SHA-256 must match, and safe-extracts only regular files/directories. Traversal, absolute paths, symlinks, hardlinks, devices, FIFOs and duplicate archive members are rejected.

Default hosted uploads use 48 MiB parts. The receiver accepts at most 64 MiB per request, 128 parts per bundle and 4 GiB per bundle. The uploader retries only bounded transient HTTP/network failures; part replays are idempotent only when size and SHA-256 are identical.

The temporary Cloudflare Quick Tunnel is transport-only. It exposes the write-only bearer-authenticated receiver, not the Atlas viewer. No public Atlas hostname, Cloudflare Access application, edge cache, Pages, R2 or object-storage publication is enabled by this path. The tunnel and random bearer capability are removed after the deployment attempt; failed/incomplete generation data may be retained on Synology for inspection, but its bearer token is removed.

## Generated corpus boundary

Full PNG/environment/browser corpora are **not** uploaded as GitHub Actions artifacts. Actions artifacts remain compact control/evidence only: planner assignment, per-shard evidence/manifests and global deployment-source evidence.

For deployment, the verified generated bytes stream directly from their hosted render job to the private Synology ingest generation. This avoids both re-rendering on the NAS and staging the proprietary-derived corpus in GitHub artifact/object storage.

## Synology paths

Canonical private deployment root:

```text
/volume1/docker/otheryn/atlas
```

Important children:

```text
current/                       active Atlas corpus
previous-<generation>/         immediate rollback generation
failed-<generation>/           failed promoted generation retained for inspection
deployments/<generation>.json  durable deployment receipt
ci-ingest/<generation>/        temporary incoming generation
project/                       existing Container Manager compose/nginx project
```

A deployment captures the initial `current/manifest.json` SHA-256 before the long hosted build. Promotion is refused if `current` appears, disappears or changes before finalization.

## Runtime activation

Only after the assembled corpus passes the existing full publication gate does deployment rename it to `current`. The workflow then recreates only the `atlas` service from the already-staged `otheryn-atlas-preview` project and requires:

- container Docker health `healthy`;
- `/healthz` exact body `ok`;
- served `manifest.json` schema version 3;
- exactly 3494 served chunks.

Failure after promotion invokes exact-generation rollback and recreates the previous Atlas runtime. Successful activation records `status: ACTIVE` and keeps only the immediate `previous-*` generation for rollback.

## Deployment request

`OTBM Atlas Synology Deployment Request` watches only:

```text
deploy/otbm-atlas-ci-ingest/deployment-request.json
```

on `main`. The request is code-reviewed through a normal PR and must contain:

```json
{
  "schemaVersion": 1,
  "requestId": "unique-request-id",
  "deploy": true,
  "target": "private-synology",
  "fullWorldCertificationRequired": true,
  "generatedCorpusArtifacts": false
}
```

The push workflow dispatches the canonical full-world workflow with the exact request commit SHA. The deployment workflow rejects a request if `main` has moved and its producer SHA no longer matches the authorized SHA.

## Recovery

`deploy/otbm-atlas-smb-transfer/publish.ps1` remains the manual Windows/SMB bootstrap/recovery path. It is no longer intended to be the canonical successful-release path once automated deployment is proven.

Do not recover by starting a full-world render on Synology. Render compute remains GitHub-hosted.
